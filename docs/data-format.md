# Release result layout

Every finalized execution is stored under its campaign and a unique execution
ID:

```text
results/<campaign-id>/<execution-id>/
├── index.json
├── raw/
│   └── <campaign>-p<placement>-r<replica>-raw.json
├── cases.csv
└── comparisons.csv
```

One raw file contains every variant for one placement and replica.

## Authority and derived views

The schema-valid files under `raw/` are the source of truth. They retain every
timing sample, case failure, workload digest and semantics, software identity,
dependency version, affinity outcome, source commit, and cloud/boot identity.

`index.json` records the release manifest, hardware epoch, source identity, and
raw files by placement. `cases.csv` and `comparisons.csv` are deterministically
regenerated by `clifft-bench finalize`; they introduce no facts absent from the
raw results or release manifest.

- `cases.csv` contains one row per case, placement, and replica, including
  failures, median/MAD summaries, the exact simulator version, and its public
  display version. Failed cases retain `error_phase`, `error_type`, and
  `error_message`; their throughput summary fields are blank, including when
  raw JSON retains samples collected before a later failure. Setup failures
  may have no calibration record or selected batch size.
- `comparisons.csv` joins manifest-declared baseline and candidate variants for
  the same workload, placement, and replica. It carries both sides' mode,
  batching, shots-per-call configuration, exact versions, and display versions.
  Only successful pairs produce comparison rows.

`tuning_policy` in `cases.csv`, and `baseline_tuning_policy` /
`candidate_tuning_policy` in `comparisons.csv`, distinguish the historical
`grid-v1` search, the new `bounded-v2` search, and fixed settings. Old calibrated
records without a policy field remain `grid-v1`.

Individual samples remain only in raw JSON. Plotting and reports should consume
the long-form CSV tables rather than add another checked-in data representation.

`cases.csv` includes `clifft_scheduler` (the pass options as JSON when enabled,
otherwise blank), `compile_seconds`, and `peak_active_width`.
Missing costs in older raw records remain blank; omitted Clifft scheduler
settings mean disabled. Full search counters and calibration timings remain
in raw JSON.

`batch_parameter` names the adapter's batching control; for Tsim it is
`statevector-batch-shots`. `batch_size_applicable` is `false` when a compiled
Tsim program has only direct outputs and ignores that control, and `true` when
statevector components exist. It describes the program, not the survivors in
an individual call. The numeric `batch_size_effective` remains the configured
API capacity, not a count of allocated quantum lanes. Missing applicability
metadata is exported as blank (unknown), preserving older records.

Plots, tables, and prose use `simulator_display_version` in `cases.csv` and the
corresponding `baseline_simulator_display_version` and
`candidate_simulator_display_version` fields in `comparisons.csv`. The adjacent
`*_simulator_version` fields retain the exact artifact version for audit and
must not be substituted into public labels when a distinct display version is
present.

## Hardware changes

Absolute throughput is comparable only within one hardware epoch. A new host
creates a new epoch. When practical, measure one anchor implementation on both
hosts and label the boundary explicitly.
